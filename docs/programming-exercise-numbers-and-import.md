# 编程题编号与 ICPC 导入

编程题使用数据库保存的 `exercise_number`，格式为 `P-000001`。创建题目时由 Frappe 命名序列分配，数据库唯一索引兜底；删除题目不回收编号，编辑或发布题目新版本不改变编号，复制题目会分配新编号。迁移补丁按旧题创建时间补号，不修改旧题的更新时间；再次执行不会改变已分配编号。

题目列表和编辑窗口显示编号。列表搜索同时匹配标题和编号；搜索时分页从第一页重新开始，计数沿用相同条件和用户权限。新题成功入库后清除旧搜索条件并刷新列表。

## 导入流程

1. 上传私有 ZIP/KPP，后台检查包结构及 PDF 题面。
2. 核对题面、语言、时间与内存。时间默认 2 秒，由教师确认；包内 MiB 内存限制按 1024 换算为 KiB。
3. 点击「导入到题库」，系统依次创建版本并发布题目。只有发布成功后才显示成功和题目编号。发布失败保留已确认的草稿，可点击「重试导入到题库」。

仍支持 legacy ICPC 标准输入输出子集，不执行包内参考程序或输入校验器。自定义输出校验器、交互题等未支持语义继续明确拒绝。

## 容量

| 项目 | 上限 |
| --- | --- |
| 上传 ZIP/KPP | 20 MiB，另受站点上传配置限制 |
| 解压总量 | 128 MiB |
| 单个文件 / 单个输入 | 16 MiB |
| ZIP 条目 | 2000 |
| 测试用例 | 100 |
| 内存 | 1024 MiB / 1048576 KiB |
| `limits.output` | 最大 8 MiB；未声明时保持 256000 字节 |

不再单凭高压缩率拒绝合法的重复数字输入，仍检查实际解压大小、总量、路径穿越、重复路径、符号链接、加密条目等。`limits.output` 传入判题配置和 Judge0 的 `max_file_size`，不会被静默忽略。发布时检查正在运行的 Judge Service 所声明的输入、输出和内存容量。

部署需同时更新 `JWLCode-judge-service`；Judge0 配置中 `MAX_MEMORY_LIMIT=1048576`、`MAX_MAX_FILE_SIZE=8192`。`docker/redeploy.sh` 负责构建前端、编译翻译和站点迁移。

## 验证

用户提供的 `icpc_maxsubarraysum_store.zip` 包含 5 个公开样例和 18 个隐藏用例，最大隐藏输入 2220007 字节，声明内存 1024 MiB、输出 8 MiB。原 ZIP 和 DEFLATE 压缩版本都通过结构检查。回归测试覆盖高压缩率、实际解压上限、输出限制、编号不可变、删除不重排、复制与补号、标题/编号搜索及导入失败后重试。

本地站点验证：原有 82 道题已补号；示例题「最大连续子段和」编号 `P-000083`。浏览器分别验证压缩版新建和原 ZIP 更新，编号一致，标题与编号均返回唯一结果。真实提交通过全部 23 个用例（100 分）。前端回归 26 项、解析器回归 30 项、站点集成 12 项、判题服务回归 33 项通过；比较器通过 314 组固定官方参考差分验证。
