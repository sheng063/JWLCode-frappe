# LMS 判题与学生导航修复验收

日期：2026-09-13。云端：120.48.133.64；本地：school.localhost:8000。

## 已确认的问题与修复

- **课时响应乱序**：先点击 1-2、再点击 1-3，延迟的 1-2 响应会覆盖当前课时。
  修复前地址为 1-3，标题却为“初始C++”；下一步仍指向当前地址，表现为点击无效。
  现在取消旧请求并丢弃旧成功/失败响应，下一步依据当前路由和章节目录计算。
- **嵌入组件生命周期**：清理视频和播放器实例，取消视频计时器与下载。EditorJS 的
  `normalize()` 会删除 Vue Fragment 的空文本锚点，导致切换时报 `nextSibling` 错误；
  视频、PDF、测验等 Vue 块使用保留这些锚点的容器。异步编辑器使用独立 holder，
  避免上一课的迟到清理影响新课。
- **相同代码替换**：Ace 先发出删除、再发出插入事件；原逻辑以尚未更新的 Vue props
  去重，遗漏最后一次输入，造成代码清空。现在按编辑器上一次文本去重，并通过真实
  Ace 双向绑定回归测试验证。
- **实时连接协议**：HTTP 80 端口无显式端口号，原代码据此误选 HTTPS；现在继承网页协议。
- **判题排队**：云端原为单进程、CPU 上限 1 核。改为两个进程、最多 2 核、CPU 权重
  512、内存上限 1 GB。结果轮询由 1 秒改为 0.5 秒。LMS 派发改到 short 队列，并增加
  独立短任务进程，避免索引、导入等长任务阻塞代码提交派发。

没有减少、跳过测试用例，也没有改变判定或评分规则。

## 性能基准与范围

同一份 C++ 加法程序、10 个合成用例、Judge0 完整结果返回：

- 原配置：8.211 秒，10/10 通过。
- 最终配置：6.575 秒，10/10 通过，缩短约 19.9%。
- 程序本身最大执行用时约 4 毫秒，其余主要是编译、隔离与队列开销。

基准脚本：`JWLCode-judge-service/scripts/benchmark_judge0.py`。它直接测量 Judge0，
不创建 LMS 提交；正式提交端到端另由上面的回调验收覆盖。这些是固定样例的观察值，
不代表所有题目和并发负载下都能达到相同比例。Judge0 仍逐用例编译；若要显著改善
大量 C++ 测试用例，需要进一步引入编译产物复用和独立判题算力。
