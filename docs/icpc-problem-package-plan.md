# LMS 编程题支持 ICPC Problem Package：实施计划

- 编写日期：2026-09-05。
- 目标仓库：`JWLCode-frappe`，调查基线为 `57a494d` 的本地工作区。
- 联动项目：`JWLCode-judge-service`；部署变更按需落在 `JWLCode-infra`。
- 文档性质：实施方案与验收计划，尚未实现功能。判题服务依据本地文件调查，未取得可用 HEAD。

## 1. 目标与推荐决策

让教师上传题目包后，可以预览题面、公开样例和导入报告，创建或更新 LMS 编程题，再通过现有服务端判题链路完成提交、判定、成绩和课程进度更新。

推荐先交付 **legacy-icpc 非交互标准输入输出题的明确支持子集**，随后补齐输入校验、参考解验证和自定义输出校验器。`2025-09` 使用独立适配器扩展。每个阶段公开兼容矩阵，不能把“解压成功”称为完整格式兼容。

默认决策：

1. 导入题强制使用 `Judge Service`；沿用既有课程和题目关联方式。
2. 公开数据复用现有样例模型，隐藏数据继续存放于受限模型或私有文件。
3. ICPC 导入题默认仅全部通过时获得 100 分，否则 0 分；教学部分分保留为显式可选策略。
4. ICPC 导入题默认不披露隐藏用例内容；旧题保留原有教学反馈策略。
5. 导入分为上传、预检、预览、确认、发布，失败不修改当前生效版本。
6. 格式版本、部署容量限制、教学策略分别记录，不能混为规范要求。

## 3. 格式基线与兼容范围

官方区分 `legacy-icpc` 与 `2025-09`：旧版题面目录是 `problem_statement/`，新版为 `statement/`。不能只根据 ZIP 扩展名决定解析方式。规范入口对新版成熟度的描述与具体版本页需结合查看，因此实现应固定规范快照及校验工具版本。[官方入口](https://icpc.io/problem-package-format/)、[legacy-icpc](https://icpc.io/problem-package-format/spec/legacy-icpc.html)、[2025-09](https://icpc.io/problem-package-format/spec/2025-09.html)。

| 能力 | 第一阶段：基础子集 | 第二阶段：校验完整性 | 后续 |
| --- | --- | --- | --- |
| 单题 `.zip` / `.kpp` | 支持规范单根目录；根部直接放内容可作为显式宽松选项并记录警告 | 保持 | 批量单题导入 |
| `legacy-icpc` | 支持非交互、默认输出校验子集 | 增加自定义非交互校验器 | 交互题专项 |
| 未声明格式版本 | 标记为 legacy 家族，按目标子集检查；不能直接认定为 legacy-icpc | 扩展诊断 | 完整 legacy 适配按需 |
| `2025-09` / 未知版本 | 明确拒绝发布，提示版本不支持 | 保持 | 独立适配器和测试集 |
| 题面及公开附件 | PDF 展示；TeX 隔离转换，转换失败保留草稿 | 改进公式、图片及多语言支持 | 可编辑 HTML 题面 |
| 样例及秘密数据 | 按 `.in` / `.ans` 配对导入；合法空文件可接受；保留排序 | 保持 | 大文件与多层分组 |
| 默认比较及 flags | 实现并验证所声明的 flags；未实现的组合阻止发布 | 保持 | 新版本规则 |
| 输入校验器、参考解 | 检查必需结构并私有保存；清楚标记未执行验证 | 在隔离环境执行并输出报告 | 更多语言/构建工具 |
| 自定义输出校验器 | 拒绝发布，禁止降级为字符串比较 | 支持非交互协议及异常处理 | 交互协议 |
| `testdata.yaml`、复杂分组、部分分 | 检测到影响判题语义的配置就拒绝，不擅自展平 | 单独评估 | 新版适配时支持 |
| 符号链接 | 首版统一拒绝并说明是产品限制 | 可评估安全解析包内链接 | 不允许越出题目包 |
| 导出 | 暂不提供重新生成的标准包 | 可提供管理员下载原始包 | 增加可校验的标准导出 |

严格导入需要检查所选规范要求的题面、秘密数据、参考解与输入校验器等结构；缺失时不能标记为有效标准包。若以后提供“仅提取题面和数据”，应另设宽松模式并记录不兼容原因。

以上是产品支持范围，不代表规范禁止其他能力。具体字段、默认值、时间预算和校验器协议，以固定版本规范和差分测试为准。

## 4. 架构与数据设计

### 4.1 导入流水线

```text
教师上传私有题目包
  → 后台安全解包与版本识别
  → 生成不可变文件清单、结构错误和能力报告
  → 转换题面、整理样例、计算生效配置
  → 教师预览并确认目标题目
  → 创建草稿版本及私有判题数据
  → 必要检查通过后原子切换生效版本
  → 提交固定题目版本 → Judge Service → Judge0 / 比较器
  → 鉴权回调 → 根据反馈策略返回结果
```

建议新增 `lms/lms/problem_package/`，分别负责归档安全、版本适配、内部模型、数据映射、导入服务和报告。解析器尽量不依赖 Frappe，便于用小型夹具测试。包内程序不得在 Web 请求或普通 Frappe Worker 中执行。

### 4.2 建议新增和扩展的数据

| 对象 | 建议字段与职责 |
| --- | --- |
| 新增 `LMS Problem Package Import` | 上传者、私有原包、SHA-256、状态、目标题目、预检清单、错误报告、过期时间；只对授权管理者开放 |
| 新增 `LMS Problem Package Version` | 所属题目、包 UUID、格式版本、内部修订号、原始 metadata、manifest、校验状态、题面文件、实际判题配置和配置摘要；发布后不可变 |
| 扩展 `LMS Programming Exercise` | `source_type`、`active_package_version`、`scoring_mode`、`feedback_policy`；展示标题/题面可作生效版本的投影 |
| 扩展 `LMS Judge Test Case` | `package_version`、`case_id`、`relative_path`、`sequence`，后续增加私有输入/答案文件引用 |
| 扩展提交记录 | `package_version`、判题配置摘要、独立 attempt 标识；版本在接受提交时固定，不能等队列执行时再决定 |

首版容量范围内可复用数据库文本存储；原文件及清单仍应保留字节哈希。大文件引入文件传输后再扩大容量，不能单纯提高 JSON 限额。

样例视图、题面、秘密测试均来自同一版本。UUID 用于提示可能更新对象，不能绕过权限自动覆盖；同一用户/目标/包哈希/配置的重复确认应幂等。无 UUID 时由系统产生内部标识，不冒充来源 UUID。

### 4.3 文件访问边界

原包、秘密数据、参考解、输入和输出校验器、管理员报告都保持私有。公开题面、样例和附件采用明确允许列表，经课程/题目访问权限校验后提供下载。禁止把整个解包目录公开挂载。

Frappe 通用文档读取、文件下载、报表导出和提交记录均需纳入权限检查；仅隐藏前端字段不足以保护秘密数据。新版本 DocType 不授予学生读取完整记录的权限，学生使用裁剪后的展示接口。

## 5. 导入与教师操作

建议 API 放在 `lms.lms.problem_package.api`，名称为设计建议：

1. `create_import(file_id, target_exercise?)`：校验文件所有权、创建/修改目标权限，创建后台任务，返回导入 ID。
2. `get_import(import_id)`：返回当前用户可见的状态、错误、警告和预览摘要。
3. `commit_import(import_id, expected_target_version, options)`：确认语言、题面和部署限制，验证预检产物未变，创建草稿版本；并发冲突返回明确错误。
4. `publish_version(version_id)`：检查版本已就绪，短事务切换 active pointer；失败保留原版本。

前端在编程题列表和表单提供“导入 ICPC 题目包”。预览包括标题、来源、格式版本、样例数、隐藏用例数、题面语言、容量和执行限制，以及阻止发布的原因。隐藏内容仅在有管理权限的详情页显示。

时间限制应显示来源：人工指定、平台策略或参考解测量。不要把 legacy 的倍率误当秒数，也不要直接使用未经确认的默认 2 秒。首版可要求教师确认实际秒数，第二阶段提供测量依据。内存单位统一到服务端实际单位，明确 MiB 与字段名 KB 的转换并测试边界。

TeX 转换放入隔离进程，限制资源、禁用 shell escape 和网络访问；缺少依赖、超时或渲染失败时阻止发布并保留报告。PDF 可先作为题面预览/下载，不承诺无损富文本转换。无公开样例的包仍可发布，学生页应显示“暂无样例”，并调整运行按钮行为。

## 6. 判题服务改造

### 6.1 保留编排，分离执行与答案比较

当前客户端将答案交给 Judge0。新建 ICPC 判定路径：Judge0 负责执行和运行错误；成功完成的 stdout 交给与所选规范一致的默认比较器。旧题维持原判定路径，按明确的模式字段路由。

比较器至少覆盖 token、大小写、空白敏感和浮点误差参数；使用参考工具进行差分验证，不用 `strip()` 相等替代规范比较。输出截断、缺失、编码失败必须得到明确结果，不能误判 AC。

在 `models.py` 扩展协议版本、题目版本、case ID、比较参数和计分模式。Frappe 按服务端 capability 判断可发布能力；不支持的请求不能静默忽略新增字段。接口发布时服务端先兼容旧请求，再切换 Frappe。

首版沿用最多 100 个用例等现有限制并在导入时提前检查。后续通过分批调度、固定顺序聚合和文件引用扩容，限制并发、输出、运行总时长与存储配额；文件访问只允许受控服务端资源，不接受任意下载 URL。

### 6.2 第二阶段：校验器与参考解

新增专用隔离执行能力，分别验证输入数据、参考解和自定义输出。构建步骤同样运行于沙箱，不持有业务凭证，也不访问数据库或宿主机服务。

自定义输出验证器必须遵循所选版本的调用与退出码约定；崩溃、超时或异常退出归为判题系统故障，不能归责为学生答案错误。管理员诊断反馈与学生反馈使用不同存储和返回通道。

参考解全通过作为第二阶段发布门槛；错误解与超时解用于回归。将工具链版本、执行报告和实际限制记录进题目版本。运行时不支持的校验器/参考解语言应阻止对应验证状态变为通过。

### 6.3 成绩、反馈与重判

- ICPC 模式全部通过才记为 Accepted/100；其他判定不产生部分分。系统错误保持可重试，不计为学生失败。
- 当前通过比例计分保留给旧题和显式教学模式。
- ICPC 严格反馈不返回秘密输入、答案、stdout、stderr 或含秘密内容的校验消息；公开样例可显示具体差异。
- 回调按 attempt、请求 ID、版本及状态版本关联；结果中的 case ID 必须属于该次请求。
- 发布新版本不改变排队或已完成提交的依据。重判新建 attempt，保留原结果与课程成绩更新轨迹，避免旧回调覆盖新判定。

## 7. 安全、失败处理与兼容迁移

归档预检拒绝路径穿越、绝对路径、符号链接、重复路径和大小写折叠冲突；限制压缩包大小、解压总量、文件数、单文件大小和压缩比。禁止递归解开任意嵌套归档。YAML 使用安全解析，限制大小、深度和别名展开，重复键作为错误。

错误报告指明路径、字段和修复建议。首版超容量、未知版本和不支持的判题模式都应在发布前失败。临时文件设清理策略；数据库提交失败时回收新建文件，避免残留半题目。

迁移采用新增字段和表，旧题默认 `source_type=manual`，保持现有数据和教学策略。不要把旧答案字段全局取消校验；区分空答案合法性与是否缺少必需数据。

上线使用功能开关。先部署判题协议支持，再迁移 Frappe，最后开启导入。回滚时关闭新导入及新版本发布，恢复旧生效指针；保留已被提交引用的版本和结果，直到相关任务结束并满足保留策略。

## 8. 实施拆分、依赖与工期估算

以下是初步工程估算，以一名熟悉项目的全栈开发者为基础；不含等待部署资源和运行时镜像准备。阶段边界以验收结果决定。

| 工作包 | 交付内容 | 依赖 | 估算 |
| --- | --- | --- | --- |
| P0：规范与夹具 | 固定规范/工具版本、兼容矩阵、代表性小包、Judge0 比较与内存实测 | 无 | 2–3 人日 |
| P1：数据与安全解析 | 版本/导入模型、归档预检、格式适配、样例/隐藏数据映射、迁移 | P0 | 4–6 人日 |
| P2：导入体验 | 异步 API、权限、题面渲染、预览确认、幂等与原子发布 | P1 | 4–6 人日 |
| P3：基础判题兼容 | 默认比较器、严格反馈、ICPC 计分、固定提交版本与回调校验 | P0、P1 | 4–6 人日 |
| P4：集成与灰度 | 后端/前端/端到端验证、容量测试、运维文档、功能开关 | P2、P3 | 3–4 人日 |
| P5：程序验证能力 | 隔离构建执行、输入校验、自定义 checker、参考解验证 | P4 | 6–10 人日 |
| P6：扩展 | 2025-09、大数据、导出、交互题；拆开立项 | P5 | 完成 P0 后分别估算 |

基础可用版本 P0–P4 约 **17–25 人日**；补齐第二阶段约再 **6–10 人日**。PDF 可用而复杂 TeX 暂不支持的场景应明确呈现为受限发布，不能以牺牲题面正确性压缩工期。

建议按工作包拆 PR；模型/API 契约先稳定，再接入前端。优先级为：版本和数据隔离 → 正确比较和反馈 → 教师导入体验 → 校验器与扩展格式。

## 9. 验证与验收标准

### 自动化验证

- 解析夹具：合法最小包、无样例包、空答案、多语言题面、缺配对文件、缺必需程序、无版本、未知版本、重复 YAML 键及不支持的 flags。
- 归档测试：穿越、链接、路径冲突、超限、压缩炸弹；只使用可控的小型构造夹具。
- 比较器差分：大小写、空白、浮点临界值、额外 token、输出截断；结果与固定参考工具一致。
- 权限集成：教师授权、跨题修改、上传文件归属，以及学生通过详情、下载、通用 API、报表和提交记录访问秘密信息的负面用例。
- 版本一致性：重复确认、两个教师并发发布、导入中断、队列等待期间发布新版本、重复/乱序回调及旧 attempt 回调。
- 判题回归：旧题保持现有行为；新题 AC/WA/TLE/RE/CE/System Error 正确，课程进度和成绩策略一致。
- 前端与端到端：上传 → 报告 → 预览 → 发布 → 学生运行样例 → 提交 → 查询成绩；覆盖无样例及失败报告。
- 容量边界：100 与 101 用例、字符串长度和 UTF-8 字节差异、时间/内存边界、受限输出及并发任务恢复。
- 第二阶段额外测试：校验器异常退出、构建失败、资源越限、参考解不通过、管理员日志不向学生泄露。

优先扩展 `lms/tests/test_judge_service.py`、`frontend/src/tests/programmingExerciseForm.test.ts` 和判题服务 `tests/test_judge0.py`，另建专用解析/比较器测试模块。具体测试命令沿用各项目现有配置，并在实际实现 PR 中记录执行结果。

### 发布门槛

1. 已声明支持范围内的真实题目包和自有夹具能导入、预览并完成服务端判题。
2. 不支持的语义、超容量和非法包在发布前给出明确错误，不丢数据后继续导入。
3. 无公开样例、合法空答案和稳定用例顺序均通过端到端测试。
4. 学生无法获取任何秘密数据、参考解、原包和内部诊断。
5. 同包重复操作不产生意外副本；发布失败不影响现用题目。
6. 新旧判题路径回归通过，版本切换和重试不串题、不串结果。
7. 管理员能区分“结构通过”“程序未验证”“已完整执行验证”，不误导为全格式支持。
