# 课程 ZIP 格式 v2

课程导出包在原有 `course.json`、`chapters/`、`lessons/`、`assessments/` 的基础上，增加：

- `manifest.json`：`format: "lms-course"`、`version: 2`，以及 `programming_exercises` 列表。
- `programming/*.zip`：每道 ICPC 题目的完整原始题包，包括题面、公开/隐藏测试数据、参考程序和校验程序。共享题目只打包一次。
- `assets.json`：附件原 URL、包内路径、文件名和私有属性，用于导入后重写引用。

每条 ICPC 映射包含源题目内部 ID `exercise`、`source_type: "icpc"`、包内 `file` 路径、`sha256`，以及 `options`（题面路径、语言、时间和内存限制）。普通编程题继续保存为 assessment JSON，其隐藏用例由 manifest 携带。

课时 JSON 显式保留 `lesson_type`。只含编程题的历史课时即使旧记录标成 `Text`，也会导出为 `Programming`；混合正文和编程题的非法课时必须先拆分。

## 导入顺序与回滚

1. 检查课程结构、所有题目引用、题包 SHA-256 和 ICPC 结构；缺少题目或题包立即拒绝。
2. 在同一个请求事务内保存私有题包、同步检查、确认配置并发布全部编程题；调用现有 ICPC 导入服务与评测能力校验。
3. 全部题目成功后，导入附件、文本和其他测评，再通过源 ID → 目标 ID 映射连接章节、课时和题目。不会按标题猜测关联；同名章节、同名题目和重复引用均保留独立身份。
4. 任意步骤异常会回滚整个请求，包括已创建的题目、版本、导入记录、课程和附件。使用 Frappe 的完整回滚及文件回滚钩子，不能替换成仅 SQL savepoint 的回滚。

一个包内同一题目只导入一次。普通题会生成新的题目 ID/编号；ICPC 服务可按其确认键复用同内容、同配置的已导入版本。目标已有题目不会按同名规则被覆盖。

旧版完整文本/普通题课程包仍可导入；旧包如果只有 ICPC 的版本引用而没有原始题包，会提示重新导出。包内总未压缩容量上限 512 MiB，单个 ICPC ZIP 上限 20 MiB。

ICPC 的检查沿用现有服务能力：校验包结构、执行配置和评测协议，并不在课程导入过程中执行参考程序或输入校验器。

## 回归验证

`lms/tests/test_course_bundle.py` 覆盖混合课时类型、同名映射、重复引用、缺题拒绝、完整 ICPC 往返、第二题失败回滚、课程文本失败回滚、题包文件清理、旧文本包和私有附件。

本地容器如果使用 Bench 内的代码副本，测试时可通过 `PYTHONPATH=/workspace/lms` 指向挂载的最新仓库。仓库文件更新不会自动覆盖 Bench 中已安装的副本。
